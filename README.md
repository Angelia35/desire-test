# 测测你最强的隐藏欲望

一个**手机端优先**的原创娱乐性格测试网页 MVP。  
目标：验证用户是否愿意完成一个在线性格测试，不做平台、不做后端。

> ⚠️ 本测试仅用于娱乐和自我探索，不构成心理、医疗或专业诊断。

---

## 功能

- 首页介绍 → 开始测试 → 20 道情境单选题（每题一个卡片）
- 点击选项后 100~200ms 即时反馈并自动进入下一题（无“下一题”按钮）
- 支持「上一题」修改之前的答案（修改不会重复累计分数）
- 六种隐藏欲望类型：灯塔型 / 风筝型 / 舵手型 / 皇冠型 / 港湾型 / 火花型
- 归一化评分（按 `rawScore / 理论最高分` 排序），首/副类型 + 并列处理
- 结果页：情绪价值标题 + 六维横向进度条 + 完整解析（6 段）
- **生成结果卡**：纯前端 Canvas 绘制竖版图片（1080×1440），手机可长按保存
- 进度自动存入 `localStorage`，刷新可恢复；完成后支持「重新测试」
- 纯静态、无服务器、无数据库、无登录、无 AI API、无后端依赖

## 本地运行

不需要任何构建步骤，直接打开即可：

**方式一：双击打开**
直接双击 `index.html` 用浏览器打开（推荐 Chrome / Safari）。

**方式二：本地静态服务器（更贴近真实部署）**

```bash
# 任选其一，在 desire-test 目录下执行
python3 -m http.server 8080
# 或
npx serve .
```

然后访问 `http://localhost:8080`。

> 使用本地服务器时，`localStorage` 行为与线上一致，方便验证“刷新恢复进度”。

## 部署

纯静态文件，可直接部署到任意静态托管平台：

### GitHub Pages
1. 将 `desire-test/` 内容推送到仓库（如放到仓库根目录或 `/docs`）。
2. 仓库 Settings → Pages → Source 选择对应分支与目录。
3. 访问生成的 `https://<用户名>.github.io/<仓库>/`。

### Cloudflare Pages
1. 连接 Git 仓库，或本地用 `wrangler` 部署。
2. 构建命令留空，发布目录设为 `desire-test/`（或包含这些文件的目录）。

### Netlify
1. 拖拽 `desire-test/` 文件夹到 Netlify Drop，或连接 Git。
2. 构建命令留空，发布目录设为包含 `index.html` 的目录。

## 评分说明（供扩展参考）

- 每选中一个选项：对应人格 **+2 原始分**。
- 各类型理论最高分 = 题库中出现机会数 × 2（B/R = 28，F/C/S/N = 26）。
- 归一化分 = `原始分 / 理论最高分`，按此排序得主/副类型。
- 首、副归一化分相同时：看最后 5 题（Q16~Q20）并列类型被选中次数，多者为主；仍相同则显示「双核心型」。**不使用随机**。

新增第二个测试时，只需替换 `data.js` 中的 `DATA`，评分引擎（`app.js` 的 `resolveResult`）无需重写。

## 自检脚本

项目内置两份自检脚本，均非交付运行所需，部署时可直接忽略。

### 1. 评分逻辑回归（纯 Node，无依赖）

```bash
node test.js
```

覆盖：题库完整性、六种类型均可触发、归一化排序、并列处理（末 5 题破平 / 双核心型）、修改答案不重复累计、20 题可完整作答。

### 2. 真实无头浏览器回归（开发用）

`test-e2e.js` 使用 `puppeteer-core` 驱动系统 Chrome，跑完整流程：375px 首页无横向滚动、20 题答题、结果页渲染、生成 Canvas 结果卡、刷新恢复进度、重新测试清空状态，并在 `screenshot-home.png / screenshot-quiz.png / screenshot-result.png` 保存截图。

```bash
# 一次性环境准备（managed node workspace）
mkdir -p ~/.workbuddy/binaries/node/workspace
cd ~/.workbuddy/binaries/node/workspace
npm install puppeteer-core@23

# 启动本地静态服务并跑回归
cd <项目目录>
python3 -m http.server 8123 &      # 或任何静态服务器
NODE_PATH=~/.workbuddy/binaries/node/workspace/node_modules \
  ~/.workbuddy/binaries/node/versions/22.22.2/bin/node test-e2e.js
```

## 关于需求文档与题库机会数的一处不一致

需求文档的「机会数」小节写的是 **B=14, R=14, F=13, C=13, S=13, N=13**（理论最高 28/26…）。

但按逐题映射实际统计为 **B=14, R=14, F=14, C=12, S=13, N=13**（理论最高 28/28/24/26/26）。即 F 多 1、C 少 1，两者之和仍为 80。

为保证归一化分恒 ≤ 1（百分比展示正确，且新增测试无需手改配置），评分引擎 `app.js` 的 `getMaxScores()` 直接从题库推导 `maxScore`，不依赖手写固定值。最终各类型理论最高分：

| 类型 | B | R | F | C | S | N |
| --- | --- | --- | --- | --- | --- | --- |
| 机会数 | 14 | 14 | 14 | 12 | 13 | 13 |
| 最高分 | 28 | 28 | 28 | 24 | 26 | 26 |

六种类型仍可全部作为主类型被触发（`node test.js` 已验证）。
